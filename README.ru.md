## 🎯 Проблема

Работа ночного клуба — это логистическая задача, замаскированная под вечеринку:

- Гости звонят, пишут в соцсети или стоят в очереди только ради вопроса «есть ли свободный стол?».
- Менеджеры ведут гостевые списки в таблицах и чатах, и каждую пятницу что-нибудь теряется.
- Депозиты за столы собираются нестабильно, а неявки стоят реальных денег.
- Промоутерам платят по принципу «поверь, я привёл 30 человек», споры о комиссиях — норма.
- У охраны нет быстрого и надёжного способа проверить, кого можно пускать.

## ✨ Решение

**OnlyClub** переносит всю ночь в Telegram, где гости и так находятся. Не нужно ставить приложение и создавать аккаунт: авторизация приходит из самого Telegram.

От выбора стола до прохода через дверь по QR-коду каждый шаг автоматизирован, отслеживается и защищён. Побочным эффектом клуб получает чистые данные и автоматический расчёт комиссий.

## 💼 Реальное бизнес-применение

OnlyClub построен вокруг того, как настоящий клуб зарабатывает и теряет деньги.

| Боль бизнеса | Как решает OnlyClub |
|---|---|
| **Пустые столы и потерянные брони** | Гость видит актуальную доступность столов и бронирует за несколько касаний в любое время, без звонка менеджеру. |
| **Неявки (NoShow)** | Для подтверждения стола нужен депозит. Если гость не пришёл, депозит остаётся клубу. |
| **Двойное бронирование** | Брони выполняются внутри транзакций БД (Unit of Work), два гостя не смогут занять один стол. |
| **Неоплаченные брони блокируют столы** | Стол удерживается 15 минут. Если депозит не внесён, стол автоматически возвращается в продажу. |
| **Отмены в последний момент** | Ступенчатая политика возвратов отбивает желание отменять поздно, оставаясь честной к тем, кто отменяет заранее. |
| **Вход несовершеннолетних / юридические риски** | Возраст проверяется (18–60) при записи в список, и повторно охраной на входе. |
| **Перенаселение зала** | У гостевых списков жёсткие лимиты мест на каждое событие. |
| **Споры с промоутерами** | Каждый гость закрепляется за промоутером по персональной ссылке, комиссия считается системой при закрытии события. |
| **Медленный и хаотичный вход** | Охрана сканирует QR и отмечает гостя за секунды, будь то бронь стола или место в списке. |
| **Ручная бухгалтерия** | Менеджер закрывает событие и запускает расчёт и выплату комиссий одним действием. |

**Для кого:** закрытые клубы, лаунжи, event-площадки и любой бизнес с ограниченным числом мест, фейс-контролем и сетью промоутеров.

**Как это приносит деньги заведению:**
- Выше заполняемость столов благодаря self-service бронированию без трения.
- Защищённая выручка: депозиты засчитываются в минимальный чек и остаются клубу при неявке.
- Масштабируемый канал промоутеров с прозрачными автоматическими выплатами.
- Меньше времени персонала на звонки, чаты и ручные списки.

## 👥 Роли (RBAC)

На бэкенде реализована строгая ролевая модель доступа.

| Роль | Возможности |
|---|---|
| **Гость** | Смотрит афишу, бронирует столы с депозитом, встаёт в гостевой список, получает личные QR-коды для входа. |
| **Охрана** | Сканирует QR на входе, проверяет возраст, отмечает посадку за стол или проход по списку (Check-In). |
| **Промоутер** | Имеет персональную реферальную ссылку, видит список своих гостей, отслеживает накопленную комиссию. |
| **Менеджер** | Создаёт события и столы, закрывает мероприятия, запускает автоматический расчёт комиссий и управляет выплатами. |

## ⚖️ Ключевая бизнес-логика

### 🔐 Безопасность и авторизация
- Авторизация через проверку подписи Telegram **HMAC-SHA256** для init data Mini App.
- Токен имеет ограниченное время жизни (**24 часа**), что исключает подделку данных пользователя.
- Кастомный `AuthenticationHandler` для TMA встроен прямо в пайплайн авторизации ASP.NET Core.

### 🪑 Умные брони
- Стол **удерживается 15 минут**, пока гость оплачивает депозит.
- Депозит **засчитывается в минимальный чек**.
- **NoShow:** депозит остаётся клубу.
- **Возврат при отмене:**

| Время до события | Возврат |
|---|---|
| Более 48 часов | **100%** |
| От 12 до 48 часов | **50%** |
| Менее 12 часов | **0%** |

### 📝 Гостевой список
- Строгий контроль возраста: **от 18 до 60 лет**.
- Лимиты мест на каждое событие.
- Возможность записать до **3 спутников**.

### 📣 Промо-система
- Если гость пришёл по ссылке промоутера, он **закрепляется за ним на 72 часа** до начала события.
- При закрытии события комиссия промоутера считается автоматически из:
  - **фиксированной суммы за гостя**,
  - **бонусов за объём**,
  - **процента от депозитов** атрибутированных броней.

## 🏗 Архитектура

Решение построено по принципам Clean Architecture: зависимости направлены внутрь, к домену.

```
OnlyClub.sln
├── OnlyClub.Core            Доменные сущности, перечисления, бизнес-правила
├── OnlyClub.Application     Сценарии использования, сервисы, интерфейсы (порты)
├── OnlyClub.Adapters        Реализации портов приложения
├── OnlyClub.Infrastructure  EF Core, PostgreSQL, репозитории, Unit of Work
└── OnlyClub                 Minimal API хост, auth handler, exception handler, DI
```

### Технические особенности

- Glassmorphism-интерфейс на чистом CSS и **4 переключаемые темы** на CSS-переменных.
- Нижние шторки через React `createPortal`, поэтому они всегда отображаются поверх интерфейса.
- Кастомный `AuthenticationHandler` для Telegram Mini App и глобальный `IExceptionHandler`, возвращающий стандартизированные JSON-ошибки.
- Транзакции через паттерн **Unit of Work** для предотвращения двойного бронирования столов.
- Полная контейнеризация в Docker и деплой на Render.

## 🚀 Быстрый старт

### Требования

- [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)
- [Node.js 18+](https://nodejs.org/)
- [Docker](https://www.docker.com/) (рекомендуется)
- Telegram-бот, созданный через [@BotFather](https://t.me/BotFather)

### Запуск через Docker

```bash
git clone https://github.com/slayr444/OnlyClub.git
cd OnlyClub
docker compose up --build
```

### Локальный запуск

```bash
dotnet restore
dotnet run --project OnlyClub
```

Для фронтенда:

```bash
cd frontend
npm install
npm run dev
```

### Конфигурация

Задайте значения через переменные окружения или `appsettings`:

| Ключ | Описание |
|---|---|
| `ConnectionStrings__Default` | Строка подключения к PostgreSQL |
| `Telegram__BotToken` | Токен бота от @BotFather, нужен для проверки подписи init data |

Telegram Mini Apps работают только по HTTPS. Для локальной разработки пробросьте dev-сервер через туннель (например, ngrok или Cloudflare Tunnel) и укажите полученный URL как адрес Mini App в @BotFather.

## ☁️ Деплой

В проекте есть `Dockerfile` и `docker-compose.yml`, деплой выполнен на [Render](https://render.com/). Создайте экземпляр PostgreSQL, задайте переменные окружения выше для веб-сервиса и укажите HTTPS-адрес развёрнутого приложения как URL Mini App вашего бота.
